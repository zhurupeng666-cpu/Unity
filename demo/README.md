# 演示材料

## 电脑端

`admin-demo.webm` 为约 3 分钟的真实浏览器录制，无旁白，配有步骤字幕。播放或下载后可用浏览器打开。

演示范围：空列表 → **API 创建明确标记的测试记录** → React 刷新查看 → 详情/搜索/筛选 → 修改状态 → 真实停止 Go 进程后的错误提示 → 同一 JSON 路径重启 → 数据与状态保留。

本视频不能证明手机提交或真实 AR；相关验收仍待真机。截图 `admin.png` 同样使用 API 测试数据。

重新录制：先按 README 构建前端和 Go 二进制，再执行：

```sh
node scripts/record-admin.mjs work/inspection.exe
```

Linux 使用 `work/inspection`。需要 `frontend` 已安装 Playwright Chromium。录制程序使用 18082 端口，创建独立 `work/admin-demo-时间戳.json`，不会修改正式数据。录制会覆盖电脑演示文件。

## 手机端（待录制）

**尚无手机视频。** 当前环境没有 Unity 编辑器和 ARCore 真机，不能伪造视频或把屏幕固定模型当作真实 AR。

建议录制 3～5 分钟，按以下脚本操作：

| 时间 | 操作与画面 |
|---|---|
| 0:00–0:35 | 展示 Android 真机、打开应用、授权相机；显示 AR 状态及实际局域网后端地址 |
| 0:35–1:15 | 缓慢移动手机识别水平面，展示绿色轮廓；改变视角确认轮廓属于真实场景 |
| 1:15–1:55 | 点击平面放置标记，绕标记移动；再次点击移动待提交标记 |
| 1:55–2:40 | 点击输入框、优先级和按钮，确认不误放标记；填写标题与描述并提交，展示成功 ID |
| 2:40–3:20 | 电脑 React 刷新看到同一个标题及 ID，修改状态 |
| 3:20–4:00 | 停止/重启同一个 Go 服务并刷新，确认问题与状态保留；可额外展示手机断网失败提示 |

补录后放入 `demo/phone-demo.mp4` 或提供无需特殊权限的下载链接，同时更新验证记录，写明手机型号、Android 版本、Unity 版本、测试日期和结果。不要录到账号、私有地址以外的敏感数据、Token 或个人通知。
